# Aztec Web Inspector operations

## Production

- **Host:** Paiju (`paiju.tailbf2225.ts.net`), not Fuji. The public site is https://aztec-inspector.ajanderson.net/. Host-side inventory: `~/.contexts/servers/karakoram/guests/paiju/README.md` (its application list still awaits an approved update).
- **Runtime:** `/srv/services/aztec-web-inspector/stack/` holds the dedicated Compose stack and Caddyfile; `/srv/services/aztec-web-inspector/releases/` holds SHA-named static builds and the atomic `current` symlink. The repo definitions are [`deploy/paiju/compose.yml`](deploy/paiju/compose.yml) and [`deploy/paiju/Caddyfile`](deploy/paiju/Caddyfile). Caddy serves the read-only release mount on container port 8080; only `127.0.0.1:18081` is published on the host for local probes. The dedicated `cloudflared` container shares this stack's Docker network with Caddy, independent of Device Keys. The HTTP origin is loopback-only on the host; CI reaches SSH over Tailscale, not a public CI runner on Paiju.
- **Public route:** Cloudflare tunnel `aztec-web-inspector-paiju` (`d07073ae-70b0-43e0-9b2f-bb550acce41e`) routes this hostname to `http://site:8080`, with unmatched requests returning 404. In zone `67fa81d55cb9a08dde54e66714577aa9`, record `c44fbc25f9fa65fcdbd32a51f408a00a` is a proxied CNAME to `d07073ae-70b0-43e0-9b2f-bb550acce41e.cfargotunnel.com` (TTL `1`).
- **Deploy:** Push to `production` triggers [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml). GitHub Actions runs `npm ci`, tests, lint, and build; marks `dist/release.txt` with the pushed SHA; joins Tailscale with an ephemeral `tag:aztec-ci` identity allowed to reach only Paiju SSH; and transfers the build as non-sudo, non-Docker `aztecdeploy` with a pinned SSH host key. [`scripts/deploy-release.sh`](scripts/deploy-release.sh) validates and atomically publishes it; [`scripts/verify-deployment.sh`](scripts/verify-deployment.sh) checks the loopback origin's SHA, HTML, sample image, and referenced JS/CSS. Builds do not replace the live release until the transfer and validation succeed. Inspect recent runs with `gh run list --repo ajanderson1/aztec-web-inspector --workflow deploy.yml --limit 3`.
- **Verify:** Take the SHA from a successful `production` run, then compare `ssh paiju 'readlink /srv/services/aztec-web-inspector/releases/current; curl -fsS http://127.0.0.1:18081/release.txt'` against it. From this repo run `bash scripts/verify-deployment.sh https://aztec-inspector.ajanderson.net <40-character-sha>` to test the public path and assets; HTTP 200 alone could come from a stale route. The successful 2026-09-29 run `36543160001` deployed `5b8f1315fdb10e60352502252866164964adb925`, which was verified over public HTTPS after cutover.
- **Rollback:** Fuji remains the fallback during an **unagreed soak period**; do not decommission it or its Caddy route and `/home/aztecuser/aztec-web-inspector/dist/` yet. First check `curl --resolve aztec-inspector.ajanderson.net:443:46.62.195.54 -fsS https://aztec-inspector.ajanderson.net/ -o /dev/null -w '%{http_code}\n'`. For a failed Paiju public route, re-read the exact Aztec Cloudflare record, then restore **only that record** to its prior DNS-only A value `46.62.195.54`, TTL `1`; verify public HTTPS and the Fuji-pinned path. For a bad Paiju release while its route is healthy, atomically select a previously verified release rather than changing DNS; preserve the bad release for diagnosis. Fuji host inventory: `~/.contexts/servers/fuji/README.md` (its deployment entry still awaits an approved update).
- **Monitoring:** Broadpeak Uptime Kuma monitor [#7, Aztec Web Inspector (Paiju)](https://broadpeak.tailbf2225.ts.net:3001/dashboard/7) checks `https://aztec-inspector.ajanderson.net/` for the keyword `aztec-web-inspector` every 60 seconds, with three retries, existing `prod` and `paiju` tags, and **no notification channel**. It was Up (`200 - OK, keyword is found`) after setup on 2026-09-29; early Down/Pending history came from the initial wrong keyword. It proves the public page/marker is reachable, not barcode decoding or image upload. Check current status on the dashboard; host-side context: `~/.contexts/servers/karakoram/guests/broadpeak/README.md` and `~/Journal/Atlas/Kuma Master.md`.
- **Env-var copy:** `/srv/services/aztec-web-inspector/stack/.env` is runtime-only, mode `0600`, and holds `RELEASES_ROOT` and the dedicated tunnel token; never print or commit its contents. See `~/.conventions/conventions/env-vars.md` (Production deployment) for the attended server-copy procedure. [`deploy/paiju/.env.example`](deploy/paiju/.env.example) documents the non-secret key names.
